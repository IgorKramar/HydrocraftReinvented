# Размер ящиков растений

Восемь новых состояний используют **сам ящик из исходного hcBuilding2x**:
`hcFarmingLemontree00_0`, прямоугольник **110 × 123 px**. Изображение ящика
извлекается из принадлежащего моду `common/media/texturepacks/hcBuilding2x.pack`.
Доски, уголки, перспектива и цвета не генерируются заново и не растягиваются.

Предыдущая подгонка по тёплым цветам принимала стебли, плоды и часть листвы за
дерево ящика. Результат зависел от растения: у картофеля корпус сильно сплющился.
Кроме того, старый импорт возвращал размер референса, игнорируя запрошенный
200 × 320 для апельсинового дерева.

Теперь все восемь иконок имеют прозрачный холст **200 × 424**. Исходный ящик
располагается в **(45, 194)**, его нижний край — 317. Это соответствует исходному
тайлу 128 × 256 с сохранением его смещения и посадки на землю. У пяти состояний
сохранена прежняя растительность в масштабе 1:1. Томат и обе капусты полностью
перегенерированы через `fal-ai/gpt-image-1.5/edit` с настоящей прозрачностью,
затем один раз подогнаны nearest-neighbour к заданному размеру. Все растения
располагаются за исходными передними стенками ящика.

Данные референса, исходные/итоговые SHA256 и смещения:
[PLANTER_SCALE.json](PLANTER_SCALE.json).
Новые запросы fal, prompts и hashes: [PLANT_REGENERATION.json](PLANT_REGENERATION.json).

```text
python tools/fit_planter_icons.py --input-dir PRIVATE/original-icons --out PRIVATE/review
python tools/fit_planter_icons.py --input-dir PRIVATE/original-icons --out PRIVATE/review --apply
python tools/fit_planter_icons.py --check
```

Повторный запуск с уже исправленными файлами оставляет их неизменными.
Неизвестный исходный hash требует проверки раскладки, вместо слепой подгонки.

Прозрачный отступ снизу нужен для native dropped-item renderer 42.21: он
вычисляет вертикальную привязку как ¾ высоты текстуры. При высоте 320 нижняя
стенка уходила под плоскость земли; при 424 привязка равна 318, рядом с нижним
краем рисунка 317. Ящик и листва не масштабируются при добавлении отступа.

Проверено в свежем клиенте 42.21.0: новые картофель и красная капуста размещены
как world inventory items с z-offset 0. Нижние стенки видны целиком. Приватный
снимок проверки: `planter-scale/native-final.png` в отдельной лаборатории.
Совпадение с исходным ящиком проверено отдельно по пикселям атласа, 8/8 PASS;
повторная обработка оставляет все восемь файлов неизменными.

Первая ручная очистка 415 пикселей томата была недостаточной: пользователь
заметил остаточную кайму также у капуст. Эти три варианта заменены новыми
генерациями с RGBA alpha; вырезание из белого фона больше не используется.
Проверка на тёмном, сером и светлом фоне выполнена. У всех трёх новых растений
0 светлых нейтральных пикселей на границе прозрачности по диагностическому
порогу RGB min > 185, max−min < 35, alpha > 8, рядом с alpha < 8.
Все три новых состояния также проверены как world inventory items на земле
в свежем клиенте 42.21.0: `fal-clean-plants-v2/native-final.png` в приватной
лаборатории. Листва без белой матовой каймы, основание каждого ящика видно целиком.

```text
python tools/import_clean_plants.py --raw PRIVATE/fal-clean-plants-v2 --out PRIVATE/review
python tools/import_clean_plants.py --raw PRIVATE/fal-clean-plants-v2 --out PRIVATE/review --apply
```
`generate_plant_icons.py` завершает импорт этим этапом; подгонка по цветам больше
не считается конечной проверкой геометрии.
