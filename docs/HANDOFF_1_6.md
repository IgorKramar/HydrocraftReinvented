## С чего продолжать

Пользователь переносит работу на другой компьютер. Частные тестовые клиенты
и сервер завершены. На этой машине больше не запускать игровые проверки без
нового запроса. Публичный выпуск остаётся 1.5.12; рабочая версия — 1.6.0-dev.4,
игровые проверки выполнялись на Project Zomboid **42.21.0**.

- `codex/fluids-1.6.0` — реализованные этапы, включая восстановленный метанол.
  Это проверенная основа разработки, а не готовый релиз. Последняя отдельная
  проверка метанола после полного перезапуска MP ещё не завершена.
- `codex/brewery-1.6.0-wip` — эта же основа плюс незавершённое пивоварение.
  **Для продолжения разработки на другом ПК брать именно эту ветку.**
- [Подробный журнал проверок](FLUIDS_1_6_STATUS.md), [MODLOG](../MODLOG.md),
  [дорожная карта](../ROADMAP.md), [правила выпуска](RELEASING.md).

Завершённые этапы были записаны последовательно, поэтому старые ограничения
в середине журнала могут быть закрыты более поздними разделами. Не начинать

## Что осталось до релиза

1. **Пивоварение — основной незаконченный блок.** Проверить и довести черновик
   ниже в настоящей игре; затем сервер + два клиента и полный перезапуск.
2. **Метанол:** после полноценного MP-сценария завершить холодную проверку
   с теми же ID предметов и остатками. На новой машине сначала создать свои
   тестовые данные; старых частных сохранений там нет.
3. **Общий релизный прогон:** чистый профиль и копия старого сохранения,
   готовка/переливание/порча/отравление, полные производственные цепочки,
   настройки сервера, загрузка и сохранение. Сверить всю ROADMAP 1.6.0 и
   непокрытые сочетания; не объявлять совместимость со всеми модами по этим
   изолированным тестам. Задержки и потери сетевых пакетов отдельно не проверены.
4. **Оформление выпуска:** итоговый аудит, версия, двуязычные README,
   CHANGELOG и ROADMAP, пакет с проверкой содержимого и инструкция обновления.
   Только после этого merge, GitHub release и Workshop 1.6.0.

До релиза остаётся полноценный цикл реализации и проверки пивоварни,
затем интеграционная проверка и упаковка. Точный срок или процент готовности
не оценивался: оставшиеся игровые проверки могут выявить исправления.

## Черновик пивоварения: текущий замысел

Новая небольшая цепочка: 30 пшеницы + 1 хмель + 1,5 л воды, Cooking 3;
сусло в кастрюле готовится 60 минут, сгорает после 120. Оно остаётся Food
до отдельного запуска брожения с одной порцией Base.Yeast. Полный остаток
даёт 1,5 л, половина — 0,75 л, 1% — 0,015 л. Партия созревает 168 часов
до HCRBeer, без последующего перехода в уксус. Питание готового пива берётся
из native профиля игры, свежесть — 14/30 дней; индивидуальные свойства и
худшее качество должны сохраняться. Домашнее пиво не должно становиться
брендовым магазинным шестипаком. Хмель добавлен в собирательство на
август–октябрь, WildHerbs/уровень 4.

Это текущие авторские параметры черновика; пользователь отдельно не выбирал
его численные параметры. Они требуют проверки баланса и доступности.

Файлы: `tools/build_brewery.py`, `tools/brewery_catalog.json`,
`tools/test_brewery.py`; `HCR_BreweryCatalog.lua`, `HCR_BreweryForage.lua`,
`HCR_Brewery.txt`; интеграция в BrewedDrinks/Fermentation/Clock и
`tools/build_drink_fluids.py`, переводы RU/EN. Новое изображение не требуется:
используется существующая иконка кастрюли.

### Следующие проверки пивоварения

- Настоящее создание сусла из ингредиентов; отказ для сырого; обычный нагрев
  и подгорание без прямой подмены cookingTime. Проверить расход дрожжей
  и ровно одну возвращённую кастрюлю, ручной и автоматический выбор.
- Полный/половинный/1% остаток, несвежесть, порча, яд, загрязнение, подгорание;
  native профиль Beer и сохранение калорий/дозы при преобразовании.
- Границы 167,999/168 часов, смешанные партии разных возрастов, разделение,
  выгрузка участка и полный перезапуск; отсутствие лишнего питания/алкоголя.
- Реальный сбор хмеля через ISForageAction: одной регистрации таблицы мало.
- Запрет превращения домашнего пива в заводской шестипак, порции для готовки.
- MP: сервер и два клиента независимо проверяют результат, затем все три
  процесса завершаются и загружают сохранённый мир заново.

## Как продолжить на другом Windows-компьютере

Установить Git, Python 3.11+ и Project Zomboid 42.21.0 для воспроизведения
результатов. На более новой версии сначала перепроверить API и базовый запуск.
Открыть PowerShell в каталоге для проектов:

```powershell
git clone --branch codex/brewery-1.6.0-wip https://github.com/IgorKramar/HydrocraftReinvented.git
cd HydrocraftReinvented
py -m venv tools/.venv
& tools/.venv/Scripts/python.exe -m pip install lupa Pillow openpyxl
$env:PZ_GAME_DIR = 'C:\Program Files (x86)\Steam\steamapps\common\ProjectZomboid'
& tools/.venv/Scripts/python.exe tools/setup_dev.py
& tools/.venv/Scripts/python.exe tools/parse_hcr.py
& tools/.venv/Scripts/python.exe tools/variant_b.py
& tools/.venv/Scripts/python.exe tools/analyze_gaps.py
& tools/.venv/Scripts/python.exe -m unittest discover -s tools -p 'test_*.py'
```

Исправить PZ_GAME_DIR, если игра на другом диске. setup_dev может сообщить
об отсутствии LuaLS или невозможности создания ссылки; это отдельная
диагностика окружения. Для запуска без черновика пивоварни использовать
`git switch codex/fluids-1.6.0` в чистом рабочем дереве.

Для отдельной тестовой сборки (выбрать ещё не существующий каталог):

```powershell
& tools/.venv/Scripts/python.exe tools/package_preview.py --out "$env:USERPROFILE\HCR-preview-1.6-transfer"
```

В результате будет папка HydrocraftReinvented с `common` и `42`, архив
и INSTALL.txt. Скопировать эту папку в `mods` **отдельного тестового профиля**
и запускать игру с `-cachedir=полный_путь_к_профилю`. Отключить Workshop-копию
в этом профиле: одновременно должна работать только одна копия ID мода.
Пользовательские миры сначала копировать, не заменять тестовыми.

В репозитории есть native-сценарии, но нет готового переносимого запуска
частного сервера. Локальные `stage_names160.py`, `run_two_mp_server.py`,
учётные данные тестовых игроков и миры остаются на исходном ПК. Для нового
ПК создать отдельный HCRLab и свои loopback-профили; лабораторные Lua из
`tools/` не включать в пользовательский пакет. Конфигурации и секреты не
публиковать. FAL_KEY для этого этапа не нужен.

## Уже принятые решения пользователя

- Старую воду с неизвестной чистотой переносить как неочищенную, сохранив объём.
- Свежесть, яд и питание хранить собственной системой, включая смешивание.
- Выход сока одинаков при одинаковом количестве фруктов; маленькой тары
  требуется несколько сосудов.
- Худшая свежесть переносится даже в сиропы и консервы.
- Молочный кофе: 0,1 л кофе + 0,1 л молока в пустую кружку 0,2 л.
- Соевое и обычное молоко расходуются в одинаковом реальном объёме.
- Медовуха, саке и новая перегонная брага: 20 л с добавлением 18,5 л воды;
  новая перегонная брага — 14 дней, старые готовые бочки готовы сразу.
- Метанол — исходный способ из спиртного плюс переработка найденных бочек;
  не изобретать созревание лимонной браги.
